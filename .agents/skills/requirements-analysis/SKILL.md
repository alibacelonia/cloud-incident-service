# Requirements analysis

Read `project.yaml`, `docs/PROJECT.md`, current architecture, tasks, and relevant code. Identify functional and non-functional requirements, missing acceptance criteria, dependencies, and architecture impact. Preserve all explicit out-of-scope items.

Update `docs/TASKS.md` with prioritized tasks, statuses, dependencies, and observable acceptance criteria. Update architecture only for decisions required by the analyzed scope. Surface conflicts and questions instead of inventing product behavior.
